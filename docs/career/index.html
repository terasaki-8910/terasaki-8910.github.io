取り組んでいる研究

データセットごとにスキーマが異なる Linked Open Data で、SPARQL クエリを書き始めるための支援を研究しています。卒業研究ではクエリ緩和による別のデータセットへの再利用を、現在は大規模言語モデルによるクエリ例の提示を扱っています。

論文

  • 2026.11 Toward Portable SPARQL Queries Across Linked Open Data: A Query Relaxation Approach to Cross-Dataset Rewriting（Masato Hinooka, Mitsuharu Nagamori。20th International Conference on Metadata and Semantics Research（MTSR 2026）。Accepted。査読有り）国際会議に採択された研究です。問い合わせを別のデータセット向けに書き換えても答えが0件になる原因を3つに分け、原因ごとに条件をゆるめる手順を作りました。545件の問い合わせで、答えが返る割合が86.4%から90.5%に上がりました。
  • 2026.09 未知のLODデータセットに対する問い合わせのための知識獲得支援手法の検討（日野岡雅人, 永森光晴, 三原鉄也。人工知能学会 第69回セマンティックウェブとオントロジー研究会（SIG-SWO-069-08）。DOI: 10.11517/jsaisigtwo.2026.SWO-069_08）データの項目の決め方（スキーマ）はデータセットごとに違うため、初めて見る LOD に問い合わせを書くのは難しくなります。大規模言語モデルで、そのデータセットに合った問い合わせの例を示し、書き始めを助ける方法を検討しました。
  • 2026.03 クエリの再利用性向上を目的とした異なるLODデータセット間におけるQuery Relaxation に基づくSPARQL 変換手法（日野岡雅人, 永森光晴, 三原鉄也。人工知能学会 第68回セマンティックウェブとオントロジー研究会（SIG-SWO-068-02）。DOI: 10.11517/jsaisigtwo.2026.SWO-068_02）あるデータセット向けに書いた問い合わせを別のデータセットで使うと、実行はできても結果が0件になることがよくあります。条件を少しずつゆるめて、別のデータセットでも答えが返る形に変換する手法を検討しました。
  • 2024.03 表面プラズモン共鳴を用いた蛍光増強の基礎的検討（寺﨑雅人, 内海淳志。電気学会関西支部 第30回高専研究発表会）表面プラズモン共鳴は、ごく少ない量の物質を高い感度で検出できるため、バイオセンサーなどに使われています。研究室で作った金の微粒子のフィルタで、簡単な方法でも蛍光を強められるかを確かめました。フィルタの作製条件は分かりましたが、蛍光は期待したほど強まらず、原因として金の表面の状態や基板の間の距離を挙げました。

happydeck

複数のマシンで動いている Claude Code のセッションを、1つの画面で見て操作するデスクトップアプリ（Happy 経由）。個人で設計・実装。使った技術：TypeScript, React 19, Vite, Tauri v2, Zod, Vitest, GitHub Actions

Tailscale でつないだ4台のマシンの Claude Code を、1つの画面で見て作業も振りたかったのがきっかけです。Happy の中継はそのまま使い、足りない PC 向けの画面だけを Tauri で作りました（メモリは実測200MB以下）。

  • Happy の通信の部分は、公式のコードから仕様を書き起こして作り直しました。
  • 画面を自由に分割し、複数のマシンのセッションを並べて操作できます。
  • 止まったセッションも、メッセージを送ると自動で再開します。

AI に任せるときは、参考の画像や手本のアプリを添えて具体的に伝えること、報告をうのみにせず実機で確かめることを学びました。

voice-transcript

Groq の Whisper API で音声を文字起こしする、CLI とデスクトップアプリ。個人で設計・実装。使った技術：TypeScript, React 19, Vite, Tauri v2, PostgreSQL, Drizzle ORM, ffmpeg, Vitest

1時間を超える授業の音声を文字起こしするため、CLI として作り始めました。使いながら画面・履歴・録音・辞書・注釈・検索を足し、Mac と Windows で同じ履歴を使えるよう自宅のサーバーに置きました。

  • 無音の位置で区切ってつなぎ直し、1時間を超える音声も扱えます。
  • 授業用に、PC の音とマイクの同時録音と、無音での自動停止を足しました。
  • 聞き間違いは元の文を残したまま注釈で直し、辞書で次から防げます。

長い処理の異常はその場で知らせること、API キーを画面の側に持たせない設計を学びました。用語があいまいだと AI が意図と違う実装をするので、アプリの中の言葉で具体的に伝えることも学びました。

claude-usage-tray（UsageTray）

Claude の使用量（5時間のセッション枠と週の枠）を、タスクトレイとメニューバーに常に表示するデスクトップアプリ。個人で設計・実装・配布（Windows / macOS）。使った技術：TypeScript, Electron, electron-vite, Preact, node-pty, Vitest, GitHub Actions

使用量を見ながら、モデルの切り替えや並列での作業を判断したかったのがきっかけです。5時間の枠が後ろにずれていくのを防ぐため、枠が切れた瞬間に最小のコストで次の枠を始める機能も付けました。

  • API がないため、裏で起動した Claude Code から使用量を読んでいます。
  • 有料の送信は枠が切れたときだけにし、1回あたり約 $0.0016 に抑えました。
  • 16×16 のトレイアイコンでも読めるよう、数字を専用のドット文字で描きました。

「動いているように見える」ことと「正しく動いている」ことは別で、重大な不具合の多くは実際に触って見つかりました。仕様が公開されていない部分は、推測せず実験で確かめることを学びました。

HitokoePet

Claude Code のセッションの状態に反応して、作業の完了を声で知らせるデスクトップペット。個人で開発（オープンソースの petdex を取り込み、機能を追加）。使った技術：Zig（Native SDK）, シェルスクリプト, Nix, GitHub Actions

複数のプロジェクトで Claude Code を並行して動かすと、終わったものや確認待ちで止まったものを見落とすため作りました。既存の3つの実装を比べ、足りなかった複数セッションへの対応を、MIT ライセンスの petdex をフォークして足しました。

  • セッションを1匹にまとめ、確認待ちや失敗のときだけ声で知らせます。
  • 吹き出しを押すと、そのセッションが動いている端末を前面に出します。
  • Windows と WSL の Claude Code を同時に見張れるようにしました。

AI が「素材が悪い」で止まったとき、別のビューアと比べて本当の原因（縮小表示のやり方）を突き止めました。比較の相手を用意して切り分ける大切さを学びました。

AI駆動開発での学び

  • 要件・画面の方針・できたかどうかの判定は自分が持ち、実装は Claude Code に任せます。
  • 参考の画像や手本のアプリを添え、アプリの中の言葉で具体的に伝えます。
  • 報告をうのみにせず、実際に触って確かめます。うまくいかないときは、比べる相手を用意して原因を切り分けます。
